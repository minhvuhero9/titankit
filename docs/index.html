TitanKit Atlas

Giải thích bằng hình về bộ kit iOS dùng chung cho nhiều app: kit gồm những gì, một app được ghép lại ra sao, và chuyện gì xảy ra khi người dùng bấm vào app.

TitanKit là gì, nói ngắn gọn

Hình dung việc làm app giống như xây nhà. Thay vì mỗi lần xây lại phải tự đúc gạch, làm cửa, đi dây điện, ta làm sẵn một kho vật liệu chuẩn. Mỗi ngôi nhà mới chỉ cần lấy ra lắp và sơn màu riêng.

Kit

Kho vật liệu dùng chung

Nút bấm, ô nhập, màn hình đăng nhập, mua gói Pro, quảng cáo, kết nối server... làm một lần, app nào cũng dùng lại được.

App

Ngôi nhà lắp từ kit

Mỗi app (App 1, App 2...) lấy phần lớn từ kit. App chỉ tự làm những màn hình riêng của nó và chọn màu, font, logo riêng.

Lợi ích

App sau nhanh hơn app trước

App 1 làm kit kèm theo nên mất công nhất. Từ App 2 trở đi chủ yếu là lắp ráp, không cần mua design mới vẫn có giao diện chỉn chu.

Nên xem trang này theo thứ tự nào

  1. Bản đồ module: bấm vào từng khối để đọc giải thích bằng lời thường, đường nối cho thấy khối nào cần khối nào.
  2. App 1: kế hoạch làm App 1 và từng tình huống người dùng (mở app, đăng nhập, mua gói Pro), cập nhật theo tiến độ thật.
  3. Hướng dẫn sử dụng: thử tạo một app mới và xem kit sinh ra những gì.
  4. Kiến thức: giải thích các khái niệm như terminal, Tuist, Xcode, scheme khi tạo và chạy project.
  5. Theme 3 lớp: đổi màu, font để thấy một app không cần design vẫn có giao diện riêng.
  6. Backend: xem vì sao sau này đổi khỏi Firebase không phải làm lại app.

    Từ code đến app chạy trên máy: 5 chặng

    Mỗi chặng dùng một công cụ. Bạn đã đi hết 5 chặng này khi chạy được Dolingo.

    1 · GitHubKho code

    2 · miseCài đúng công cụ

    3 · TuistDựng project

    Đọc bản vẽ Project.swift và sinh ra file project cho Xcode.

    4 · XcodeBiên dịch

    Biến code Swift thành app (gọi là build).

    5 · SimulatorChạy thử

    iPhone ảo trên Mac để mở app mà không cần điện thoại thật.

    Vì sao không mở thẳng Xcode mà phải qua Tuist?

    Xcode lưu project trong file .xcodeproj. File này rất dài, khó đọc, và hay bị xung đột khi nhiều người cùng sửa. Vì vậy repo chỉ giữ bản vẽ ngắn gọn viết bằng Swift (Project.swift, Workspace.swift). Mỗi lần cần, Tuist đọc bản vẽ và xây lại file project cho Xcode.

    Giống như giữ bản vẽ kiến trúc thay vì chụp ảnh ngôi nhà. Muốn thêm phòng thì sửa bản vẽ, rồi xây lại. Với kit này, bản vẽ còn giúp tạo app mới chỉ bằng vài dòng, vì mọi app dùng chung một khuôn.

    Từng lệnh bạn vừa chạy nghĩa là gì

    Hãy tưởng tượng máy Mac của bạn là một công trường. Muốn xây được ngôi nhà (app), lần đầu phải sắm dụng cụ. Sau đó mỗi ngày chỉ việc lấy bản vẽ mới và xây.

    Phần A · chỉ làm một lần trên mỗi máy

    Sắm dụng cụ cho công trường

    1

    brew install mise

    Thuê một người quản kho tên là mise. Homebrew (brew) là chỗ thuê người.

    2

    echo ... >> ~/.zshrc và source ~/.zshrc

    Dặn terminal: "lần nào mở lên cũng gọi người quản kho có mặt". Nếu không có bước này, terminal sẽ báo command not found: mise.

    3

    mise install

    Người quản kho đọc tờ danh sách .mise.toml trong dự án, thấy ghi "cần Tuist bản 4", và đi mua đúng bản đó. Nhờ vậy máy nào cũng dùng cùng một bản Tuist.

    4

    cp ...Secrets.example.xcconfig ...Secrets.xcconfig

    cp nghĩa là copy. Lệnh này tạo một két sắt rỗng bằng cách chép từ két mẫu. Sau này API key sẽ cất trong két này. Két không bao giờ được đưa lên GitHub, nên mỗi máy phải tự tạo.

    Phần B · làm mỗi khi muốn chạy bản mới

    Lấy bản vẽ mới rồi xây

    1

    git pull

    Lấy bản vẽ mới nhất từ GitHub về máy. Nếu Claude vừa làm xong phần nào, lệnh này kéo phần đó về.

    2

    tuist install

    Gom đủ vật liệu mà bản vẽ cần. Vật liệu ở đây là các module của TitanKit như TitanCore, TitanDesignSystem.

    3

    tuist generate

    Thợ xây Tuist đọc bản vẽ và dựng khung nhà: tạo ra file TitanKit.xcworkspace, rồi tự mở Xcode.

    4

    Bấm ▶ trong Xcode

    Xcode hoàn thiện ngôi nhà (build) và cho bạn vào ở thử trên iPhone ảo.

    Tóm lại: phần A bạn đã làm xong và không phải làm lại. Từ giờ mỗi lần muốn xem bản mới, bạn chỉ chạy phần B: git pull → tuist install → tuist generate → bấm ▶. Chạy thừa lệnh nào cũng không sao.

    Tự tay dựng repo như hiện tại, không cần AI

    Đây là các bước để làm lại repo TitanKit từ một thư mục trống. Code dưới đây là bản rút gọn cho dễ hiểu. Bản đầy đủ có trong repo, thêm Dev/Staging/Prod, test và CI.

    titankit/                      ← thư mục gốc, cũng là repo git
├── .mise.toml                 ← bước 2: ghi bản Tuist cần dùng
├── Packages/TitanKit/         ← bước 3: bộ kit
│   ├── Package.swift
│   └── Sources/TitanCore/...
├── Tuist/Package.swift        ← bước 4: báo Tuist có kit
├── Workspace.swift            ← bước 4: gom các app
└── Apps/Dolingo/              ← bước 5: app đầu tiên
    ├── Project.swift
    └── Sources/DolingoApp.swift
    1

    Tạo thư mục và bật git

    Mở Terminal, gõ:

    mkdir titankit
cd titankit
git init

    mkdir là tạo thư mục, cd là đi vào thư mục, git init là bắt đầu theo dõi lịch sử thay đổi.

    2

    Ghi bản Tuist cần dùng

    File .mise.toml chỉ có 2 dòng: [tools] và tuist = "4". Cách nhanh nhất là để Terminal tạo giúp. Đứng trong thư mục titankit và gõ:

    printf '[tools]\ntuist = "4"\n' > .mise.toml
cat .mise.toml
mise install

    Dòng 1 ghi 2 dòng chữ vào file (\n là xuống dòng, > là ghi vào file). Dòng 2 in file ra để kiểm tra. Dòng 3 cài Tuist. Lưu ý: file có dấu chấm ở đầu tên là file ẩn, Finder không hiện; muốn thấy thì bấm ⌘⇧. trong Finder.

    3

    Tạo bộ kit (Swift Package)

    Đứng ở thư mục titankit và chạy một mạch. Lệnh cd nghĩa là đi vào thư mục, cd ../.. là lùi ra 2 cấp, còn pwd cho biết bạn đang đứng ở đâu.

    mkdir -p Packages/TitanKit/Sources/TitanCore Packages/TitanKit/Sources/TitanDesignSystem   # tạo kit và 2 ngăn module
cd Packages/TitanKit                # đi vào thư mục kit
echo 'public enum TitanCoreModule {}' > Sources/TitanCore/TitanCore.swift
echo 'public enum TitanDesignSystemModule {}' > Sources/TitanDesignSystem/TitanDesignSystem.swift
touch Package.swift                 # tạo tờ khai trống
open -a Xcode Package.swift         # mở tờ khai bằng Xcode
cd ../..                            # quay về thư mục gốc

    Không cần lệnh swift package init: lệnh đó chỉ tạo khung mẫu mà đằng nào mình cũng xóa và thay. Mỗi ngăn module phải có ít nhất một file .swift, nên mới cần 2 dòng echo. Khi Package.swift mở trong Xcode, dán đoạn dưới vào rồi lưu:

    // swift-tools-version: 6.0
import PackageDescription

let package = Package(
    name: "TitanKit",
    platforms: [.iOS(.v16)],
    products: [
        .library(name: "TitanCore", targets: ["TitanCore"]),
        .library(name: "TitanDesignSystem", targets: ["TitanDesignSystem"]),
    ],
    targets: [
        .target(name: "TitanCore"),
        .target(name: "TitanDesignSystem", dependencies: ["TitanCore"]),
    ]
)

    Repo thật khai báo đủ 13 module theo cùng cách này.

    4

    Báo cho Tuist biết có kit và có các app

    Tạo file Tuist/Package.swift:

    // swift-tools-version: 6.0
import PackageDescription

let package = Package(
    name: "TitanKitDependencies",
    dependencies: [
        .package(path: "../Packages/TitanKit"),
    ]
)

    Tạo file Workspace.swift ở thư mục gốc. Dòng Apps/* nghĩa là mọi app nằm trong thư mục Apps đều được gom vào:

    import ProjectDescription

let workspace = Workspace(name: "TitanKit", projects: ["Apps/*"])
    5

    Tạo app Dolingo

    Tạo file Apps/Dolingo/Project.swift. Đây là bản vẽ của app: tên, Bundle ID, và kit nào được dùng.

    import ProjectDescription

let project = Project(
    name: "Dolingo",
    targets: [
        .target(
            name: "Dolingo",
            destinations: [.iPhone],
            product: .app,
            bundleId: "com.titanstudio.dolingo",
            deploymentTargets: .iOS("16.0"),
            infoPlist: .extendingDefault(with: ["UILaunchScreen": [:]]),
            sources: ["Sources/**"],
            dependencies: [
                .external(name: "TitanCore"),
                .external(name: "TitanDesignSystem"),
            ]
        ),
    ]
)

    Rồi tạo file code đầu tiên Apps/Dolingo/Sources/DolingoApp.swift:

    import SwiftUI

@main
struct DolingoApp: App {
    var body: some Scene {
        WindowGroup { Text("Xin chào Dolingo") }
    }
}
    6

    Dựng và chạy thử

    tuist install
tuist generate

    Xcode mở ra. Chọn scheme Dolingo, chọn iPhone ảo, rồi bấm ▶.

    7

    Đưa lên GitHub

    Trước hết tạo file .gitignore để không đưa file rác và file bí mật lên. Ví dụ: *.xcodeproj, *.xcworkspace, Derived/, Secrets.xcconfig. Sau đó tạo repo trống trên github.com và chạy:

    git add .
git commit -m "Khởi tạo TitanKit"
git branch -M main
git remote add origin https://github.com/<tài-khoản>/titankit.git
git push -u origin main
    8

    Phần repo thật làm thêm

    Sau khi bản tối thiểu chạy được, repo hiện tại bổ sung thêm những thứ sau. Mỗi thứ là một file đọc được trong repo.

    • Ba môi trường Dev/Staging/Prod: thư mục Apps/Dolingo/Config/*.xcconfig và phần configurations trong Project.swift.
    • Ba scheme Dolingo-Dev, Dolingo-Staging, Dolingo-Prod: phần schemes trong Project.swift.
    • Test: Packages/TitanKit/Tests và Apps/Dolingo/Tests.
    • CI tự kiểm tra: .github/workflows/ci.yml và các script trong Tools/.

    Từ điển nhỏ

    Terminal

    Cửa sổ gõ lệnh

    Ứng dụng có sẵn trên Mac để ra lệnh cho máy bằng chữ thay vì bấm chuột.

    Homebrew · brew

    Kho cài phần mềm

    Gõ brew install tên là máy tự tải và cài phần mềm đó.

    mise

    Quản lý phiên bản công cụ

    Bảo đảm mọi máy (máy bạn, máy CI) dùng cùng một phiên bản Tuist.

    Giống quy định cả đội dùng chung một loại thước đo.
    Tuist

    Thợ dựng project

    Đọc Project.swift và sinh ra project Xcode.

    Bản vẽ vào, ngôi nhà ra.
    Xcode

    Xưởng làm app iOS

    Phần mềm của Apple để viết code, build và chạy app. Bắt buộc phải có để làm app iOS.

    .xcworkspace

    File mở trong Xcode

    Tuist sinh ra TitanKit.xcworkspace, gom tất cả app và kit vào một cửa sổ. Không đưa lên GitHub vì luôn có thể sinh lại.

    Scheme

    Nút chọn "chạy cái gì, ở đâu"

    Dolingo-Dev nghĩa là chạy app Dolingo với môi trường Dev. Đổi scheme là đổi môi trường.

    Dev · Staging · Prod

    3 môi trường

    Dev để làm hằng ngày, Staging để thử trước khi phát hành, Prod là bản người dùng thật tải về. Ba bản có thể cài cùng lúc trên một máy.

    .xcconfig

    File cấu hình môi trường

    Ghi các giá trị khác nhau giữa môi trường như địa chỉ server, tên hiển thị.

    Secrets.xcconfig

    Két chứa khóa bí mật

    Nơi để API key. Không bao giờ đưa lên GitHub, mỗi máy tự tạo từ file mẫu.

    Bundle ID

    Số căn cước của app

    Ví dụ com.titanstudio.dolingo. Bản Dev có thêm đuôi .dev nên không đè lên bản thật.

    TitanKit là một Swift Package chứa 13 module. App chỉ kéo vào những module nó cần.

    CI

    PR · Pull Request

    Đề xuất thay đổi

    Gói thay đổi để bạn xem trước khi gộp vào nhánh chính (main).

    Lỗi thường gặp

    zsh: command not found: ...

    Máy chưa cài công cụ đó, hoặc cài rồi nhưng terminal chưa nhận. Cài theo hướng dẫn, rồi đóng terminal mở lại (hoặc chạy source ~/.zshrc).

    Xcode báo "No such module 'TitanCore'"

    Thư viện chưa được tải hoặc project cũ. Đóng Xcode, chạy tuist install rồi tuist generate.

    Không thấy scheme Dolingo-Dev

    Bạn đang mở nhầm file. Hãy mở TitanKit.xcworkspace (Tuist tự mở sau tuist generate), không mở thư mục Packages.

    Không có máy ảo iPhone để chọn

    Trong Xcode vào Settings → Components (hoặc Platforms), tải iOS Simulator.

    Chạy lại bộ 3 lệnh tuist install → tuist generate, rồi trong Xcode chọn Product → Clean Build Folder (⇧⌘K) và chạy lại. Vẫn lỗi thì dán lỗi vào thread cho Claude.

    Design pattern sử dụng

    Mỗi pattern có lý do cụ thể. Bấm tên module để mở nó trong bản đồ kiến trúc.

    Bên trong một màn hình của app: MVVM + Repository

    View (SwiftUI)Chỉ vẽ giao diện từ state, gửi action cho ViewModel.
    ↓ action  ·  ↑ state
    ViewModel@MainActor, ObservableObject. Giữ state màn hình, gọi Repository.
    ↓
    Repository của appUserRepository, OrderRepository... trả về model Swift thuần.
    ↓ chỉ biết protocol
    Service của kitAuthService, DataService... được Composition Root (AppContainer) inject vào.

    Theme 3 lớp

    Cùng một bộ component, mỗi app chỉ đổi vài thông số thương hiệu là ra giao diện riêng. Thử đổi bên dưới: đây là cách một app mới không cần mua design.

    1
    Base theme (kit)

    Toàn bộ token mặc định và component chuẩn. Luôn có.

    2
    Brand theme (từng app)

    Màu chủ đạo, font, bo góc, sáng/tối. Kit tự sinh bảng màu đầy đủ.

    3
    Override (app có Figma riêng)

    Ghi đè token hoặc thay component. Phần còn lại vẫn dùng của kit.

    Backend không khóa vào Firebase

    App gọi protocol của kit, không gọi SDK. Chọn một adapter để xem phần nào thay đổi: chỉ đúng một tầng dưới cùng.

    Màn hình / ViewModelKhông đổi
    ↓
    Repository của appKhông đổi
    ↓
    Protocol của kitAuthService · DataService · FileStorageService · AnalyticsService · CrashService · RemoteConfigService · PushService
    ↓ AppContainer chọn adapter
